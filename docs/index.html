How it runs

Resumable at every step. An interrupted run, a fixed credential or a paused writer picks up exactly where it stopped — translations are cached, so nothing is paid for twice.

Bhashini translates. It cannot rewrite.

Bhashini is the right engine for these languages — free, government-run, purpose-built for the 22 scheduled languages. But it is a translation API. It has no ability to rewrite for tone, restructure a document for answer engines, or take feedback and improve, which is precisely what a "rewrite until it stops sounding machine-made" loop requires.

So the two jobs are split. Bhashini does translation and back-translation. A separate pluggable writer backend does transcreation, humanising, restructuring and review — either free inside a Claude Code session, or on Google AI Studio's free tier for unattended runs.

Blog Studio — the app you actually open

The pipeline above is a command-line job that pauses mid-run. Fine for a batch, wrong for something you use every morning. Blog Studio wraps it in a local browser app covering the whole blogging day.

python -m studio          # or double-click blog.bat

Runs on 127.0.0.1 only. It holds API credentials and can write to your Google Drive, so it is not reachable from the network and should not be.

Ideas: the tab that earns its place

On a site with a couple of thousand posts, the useful daily question is not “what has search volume”, it is “have we already covered this?” — because writing the same post twice splits its own rankings. Every candidate is checked against the site's own sitemap and flagged.

QueryVerdictScoreWhy
diabetes symptomscovered1.00an existing post says exactly this
diabetes symptoms in womenpartial0.80real angle the existing post lacks
thyroid symptomspartial0.80nearest post is about thyroid cancer
best pizza recipe naplesgap0.00nothing on the site is close

That third row is a bug the testing caught. The first version scored coverage in one direction only — “is the query inside the slug” — so thyroid symptoms fitted neatly inside thyroid cancer symptoms and scored a perfect 1.00, marking a different condition as already covered. It now scores F1 over content words, which penalises a mismatch in either direction.

People Also Ask is not used, because it does not work

The obvious source for “questions people ask” is Google's PAA box. It was tested rather than assumed: google.com/search returns a JavaScript-only shell to a plain HTTP client — no data-q attributes, no embedded question JSON, and not even the string “People also ask” anywhere in the 91KB response. Scraping it would need a headless browser and would break the first time Google changed its markup.

Autocomplete is a documented endpoint returning the same class of signal, so the Ideas tab expands topics through that instead — with question prefixes, modifiers and an optional alphabet sweep.

Draft, and a number that is deliberately not reused

Briefs become English posts written answer-engine-first: question headings, a standalone 40–60 word answer under each, a TL;DR, an FAQ set. Structure applied afterwards gives you an FAQ bolted on the end; writing to it gives you a post where every section is independently quotable.

English drafts are scored “AEO + rhythm”, not AI-likeness

Three of the six sub-scores below — translationese, register, script purity — measure Indic-specific phenomena that are undefined on English, and the calibration behind the AI-likeness proxy was measured on Hindi. Running it on English would produce a number that looks like the Hindi one, sits in the same column, and means something else entirely.

Drafts are therefore scored on structure, sentence rhythm, an independent editor pass and the safety rails, under a different name. The app states this on screen, next to the score.

A draft also has no source document, so the fidelity check that protects a translation has nothing to compare against. Every figure a draft contains is listed for a human to verify instead of being silently trusted.

The workbench

A page checker sees one page. Most of what matters in SEO — and nearly all of what matters in AEO — is invisible at that scale.

Site-wide crawl

Duplicate titles and bodies, cannibalisation, thin content, noindex and canonical conflicts, orphan pages, and specific internal links to add with the anchor text to use. Throttled, robots-aware, and resumable — 2,434 pages at one request a second is forty minutes, so it appends as it goes and picks up where it stopped.

The finding that was wrong, and how

The first version reported 80 broken internal links on a 60-page sample. Four were checked by hand and all returned HTTP 200 — tag and contact pages that simply sat outside the sample, inferred broken because they were not in the crawl. Orphan detection had the same flaw.

Broken links are now confirmed with a live request, and orphan and inbound-link checks are skipped entirely on a partial crawl, with the interface saying so. Failures went from 101 to 6, and those six are real. Handing a client eighty imaginary broken links would have been worse than handing them nothing.

Answer-engine readiness

Answer engines do four things — crawl, chunk, retrieve, quote — and each fails for reasons a classic SEO tool never inspects.

StepWhat is checkedWhy it fails
Reach13 AI crawlers in robots.txt — GPTBot, ClaudeBot, PerplexityBot, Google-Extended, CCBot and the restIf they are blocked, every other AEO effort on the site is wasted. Sites block them by accident constantly.
RetrieveChunk-readiness: dangling openers, missing entity anchors, oversized sectionsRetrieval judges a ~300-word chunk alone. A section opening “This means the dosage should be halved” has no antecedent once retrieved.
QuoteAttributed statistics, definitions, step lists, standalone answers, FAQ, freshnessEngines quote specific shapes. General advice does not get lifted.
AnchorEntities resolved against Wikidata for sameAsMentioning a term is a string match; linking it joins a knowledge graph.

Chunk-readiness is the measurement that separates GEO from SEO, and it discriminates sharply: a section built from dangling pronouns scores 15/100, a self-contained one 100/100.

Verified on the client site: all thirteen AI crawlers are allowed, and a well-formed 210-line llms.txt already exists. Against fixtures that block GPTBot specifically, and everything by wildcard, exactly the right agents are flagged — a checker that passes everything is worthless.

One number is deliberately absent

Whether ChatGPT or Perplexity actually names you cannot be measured without a paid provider. The hook is wired so it can be switched on, and until it is, the tool reports that it is not measured rather than producing a plausible figure nobody checked. Every other number here comes from the page or the site.

Fix-it

The audit knows the title is 16 characters. The writer can write. Until phase three nothing joined those two facts, so the tool produced homework rather than work. Fix-it applies the repairs, re-audits, and shows before and after — 44 → 72 on the test fixture, with every absolute medical claim removed and the hedges put back.

It is allowed to refuse, and it does

On its first real run the model invented five statistics, including a 279388, despite a prompt forbidding exactly that. The rewrite was rejected, retried with the violation fed back, and only then applied. On a second, thinner fixture both attempts were rejected and the original was kept.

Inventing a number always blocks. Removing one is surfaced for review instead, because in a fix that is usually the point — deleting “100% guaranteed cure” deletes the 100, and that is the single most valuable change this tool can make to health copy.

Competitors, performance, reporting

A competitor diff that returns a content-gap list rather than a score, because “you 62, them 71” is not something anyone can act on. Performance checks that need no credentials — compression, caching, viewport, image weight, render-blocking scripts — and Core Web Vitals when a free PageSpeed key is present. And a self-contained client report that prints clean to PDF, with a CSV of every finding beside it.

The score is a proxy, and it says so everywhere

There is no honest way to put a detector number on Devanagari.

No AI detector is validated on Hindi, Marathi, Gujarati, Bengali, Tamil, Telugu, Kannada or Punjabi. GPTZero and Originality.ai are English-first and their Indic output is unaudited. Printing one of those numbers next to a Hindi article would be reporting noise with a decimal point on it.

So this tool does not wrap a detector. It measures six things that are real and observable in Indic text, and reports the inverse of the composite as AI-likeness % (proxy) — the exact label used in the tracker sheet, the report and the published Doc, so it can never be mistaken for a detector reading.

Sub-scoreWhat it measures
fidelityback-translation round trip, number and dosage integrity, locked brand terms, medical-claim inflation
grammarscript purity, spaced punctuation, detokenisation artefacts
translationeseprepositional calques, English-shaped relative clauses, comma density
registerhonorific consistency, over-Sanskritised vocabulary
burstinesssentence-length variation, paragraph uniformity, repeated openings
native reviewan independent pass shown only the target text, never the source

Calibration, and what it destroyed

A quality gate whose numbers have never been tested against real text is decoration. This one was tested first — and the first version failed badly.

ClassSourceHLSAI-likeness
nativeBBC Hindi journalism92.37.7%
translatedHindi Wikipedia, rendered from English74.725.3%
raw MTunedited machine translation56.044.0%

The first version of the scorer measured AUC 0.21. It ranked translated text as more human than native text. Running the calibration falsified three assumptions that all sounded obviously correct — including the one the whole design had been built around.

“Devanagari prose ends sentences with a danda. A full stop reads as machine output.”

Backwards. BBC Hindi, written by Hindi journalists, uses a danda in 0% of paragraphs. Both machine classes used one in ~98%. The rule was not merely useless — it was penalising the most native text in the sample.

native 0.00 · translated 0.98 · raw MT 1.00 → measured, never scored

“Native prose has shorter sentences than translated prose.”

Wrong direction. Native journalism runs longer — 22.5 words per sentence against 19.4 for the translated class.

component removed from the score

“Verb-finality is the dominant translationese signal. Indic is verb-final, English is not, so translated prose keeps English clause order.”

No signal at all. Native 0.921, human-translated 0.956, raw MT 0.906. Indic NMT gets word order right. This was the headline hypothesis of the design and it now carries zero weight.

still reported for diagnosis · weight 0.00

Every falsified rule stays in the source as a documented failure rather than being quietly deleted — the reasoning that produced them is the reasoning that will produce the next wrong rule.

Two more went the same way while building Blog Studio: that gap analysis could score coverage in one direction (it rated a query about thyroid symptoms as fully covered by a post about thyroid cancer), and that Google's People Also Ask box could be read from a plain HTTP request (it cannot — the response carries no question data at all). Two more followed in phase three: that a link missing from a crawl is a broken link (a 60-page sample of hiims.in reported 80 broken internal links and the first four all returned HTTP 200 — they were simply outside the sample), and that a model listed by an API can be called (Gemini's models.list advertises models that 404 on use). Seven wrong assumptions, every one of which looked obviously correct until something measured it.

What the AEO layer adds

Search engines rank pages. Answer engines lift passages. That difference decides the whole structure.

  • TL;DR block — the passage an answer engine reaches for first
  • Question-form headings, each followed by a 40–60 word direct answer that still makes sense quoted with no context around it
  • 6–10 FAQs built from real regional query shapes, in native script and Hinglish
  • JSON-LD — Article / MedicalWebPage, FAQPage, BreadcrumbList and publisher, with inLanguage, speakable and entity anchors
  • hreflang cluster across all nine variants plus x-default, so the translations stop competing with each other
  • Transliterated Roman slugs — /hi/diabetes-ke-shuruati-lakshan/, not a percent-encoded Devanagari URL nobody can read in a SERP or paste into WhatsApp
  • Entity anchoring — named entities get cited in generated answers; pronouns do not

Rails that are enforced, not requested

Everything here is checked in code after the model replies. This is health content for Indian clinics; a politely-worded instruction is not a safety mechanism.

  • Every number in the source must survive into the translation. A 500 mg dose quietly becoming 50 mg blocks publication outright.
  • Locked brand and product names must come through unchanged.
  • No medical claim may come out stronger than it went in, and a hedge the source carried — “may help”, “consult a doctor” — may not be deleted.
  • A rewrite pass that improves the style score while breaking a fact is rejected, and the previous version is kept.
  • Anything that cannot reach the threshold is marked NEEDS_HUMAN_REVIEW and flagged red in the tracker, never silently shipped.
  • Keyword volumes are left empty when Google Ads credentials are absent. Nothing is estimated — a fabricated search volume in a client deliverable is indistinguishable from a measured one.

This page is documentation, not a running service

Blog Studio runs on your own machine, at 127.0.0.1:8765. It holds API credentials and can write to your Google Drive, so there is deliberately no hosted version that translates a URL you paste in here. Clone the repo and follow SETUP.md.

Running it

# the app: audit -> fix -> crawl -> compare -> translate -> report
python -m studio

# or the pipeline directly. one live post, Hindi, local files only
python run.py --url https://example.com/blog/post/ --langs hi --no-publish

# a sitemap, five posts, three languages, published to Docs + Sheet
python run.py --sitemap example.com --filter /blog --limit 5 --langs hi,mr,ta

# verify the gate before trusting it
python calibrate.py --fetch --build-mt-free
python calibrate.py          # expect AUC 1.00 on both classes
python test_rewrite_loop.py  # expect ALL CHECKS PASSED

Every credential is optional at install time and required at run time. Each one that is missing prints the file to create and where to get it, rather than a stack trace. A no-credential test engine runs the entire pipeline end to end so the plumbing can be checked before any registration completes.
